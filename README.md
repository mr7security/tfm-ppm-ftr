# Testing Predictive Process Monitoring Algorithms on an Inpatient Care Process (Failure To Rescue)

Code and LaTeX sources of the Master's Thesis (TFM) of Miguel Rebolledo, University Master's Degree in Intelligent Systems, Universitat Jaume I (UJI). Supervisors: Reyes Grangel and Juan Carlos Amengual.

The work builds an event log of the **elective surgical care process** from the `ftr_cige_v01` database (Hospital Universitari de La Plana, anonymized), models the process in BPMN, validates the event log with process discovery and conformance checking (ProM, Disco, Celonis, PM4Py), and compares five prediction algorithms (Decision Tree, Random Forest, XGBoost, LSTM, Transformer) on three predictions: next activity (Prediction 1), ICU admission without planning information (Prediction 2) and prolonged length of stay (Prediction 3), following the Entropy-Driven Next Activity Prediction Approach of Zare et al. (2025).

**The data are not included.** The database and the event logs contain clinical data and are available only to the research project. The scripts expect the CSV export of the database (`bbdd/`) or the event log files generated by `eventlog/build_event_log_v3.py`.

## Structure

```
bbdd/        PowerShell scripts to dump the PostgreSQL database and export its tables to CSV
             (credentials are read from a local JSON file, not included)
eventlog/    build_event_log_v3.py       builds the event log (CSV, Parquet, XES) from the CSV export
             conformance_bpmn_*.py       conformance checking of the event log against the BPMN model (PM4Py)
             mapaHospitalizacionProgramadoQuirurgico.bpmn   reference BPMN model (Camunda Modeler)
             README_eventlog_v3.md       design of the event log (activities, attributes, labels)
discovery/   make_inputs_v3.py           inputs for the discovery tools (ProM, Disco, Celonis)
ppm/         ppm_data_v3.py              loading, prefixes, encodings, temporal split, process entropy
             run_experiments_v3.py       models, metrics and figures; variants A/B/C and next activity
             run_outcome_C_cv.py         unplanned ICU admission (C) with cross-validation
             run_experiments_targets.py  postoperative complication (D) and prolonged length of stay (E)
             run_final_v3.py             the three predictions of the report in one reproducible run
             nextact_por_prefijo.py      accuracy of next-activity prediction by prefix length
             results_final/              metric tables, curves and execution log of the final run
memoria/     LaTeX sources of the report (XeLaTeX, IEEEtran bibliography)
```

## Reproducing the experiments

Python 3.10 or later with the packages in `requirements.txt` (CPU is enough; the final run takes about 10 minutes).

```
pip install -r requirements.txt
cd eventlog
python build_event_log_v3.py --csv ../bbdd/csv --out ../data     # needs the CSV export
cd ../ppm
python run_final_v3.py          # Predictions 1, 2 and 3 -> resultados_final/
python run_experiments_v3.py    # variants A/B/C and next activity
python run_outcome_C_cv.py      # unplanned ICU admission (C) with cross-validation
python run_experiments_targets.py   # complementary analyses D and E
python nextact_por_prefijo.py   # accuracy by prefix length
```

The scripts read `eventlog_pq.csv` and `eventlog_pq_casos.csv` from the parent folder of `ppm/`.

## Report

The report is compiled with XeLaTeX (`memoria/main.tex`, `latexmk -xelatex main.tex`).

## Nomenclature

In the code the experiments are identified by letters: F = Prediction 1 (next activity), A = Prediction 2 (ICU admission without planning information), E = Prediction 3 (prolonged length of stay); B, C and D are complementary analyses.
